# Politica di sicurezza / Security policy

## Italiano

### Versioni supportate

| Versione | Correzioni di sicurezza |
| :--- | :--- |
| 1.11.x (ultima stabile) | ✅ |
| Beta della versione successiva | ✅ nella beta seguente |
| 1.10.x e precedenti | ❌ aggiornare all'ultima stabile |

Le correzioni di sicurezza escono in una nuova versione e sono annunciate con un avviso di sicurezza del repository (GitHub Security Advisory).

### Come segnalare una vulnerabilità

**Non aprire una issue, una pull request o una discussione sul forum**: sono pubbliche, e renderebbero la vulnerabilità nota prima della correzione.

Segnala in privato, dalla scheda **Security** del repository, con **«Report a vulnerability»**.

Indica, se puoi: la versione di KondoManager, come riprodurre il problema passo per passo, che cosa permette di fare (quali dati, quale ruolo serve) e, se c'è, una prova.

### Che cosa succede dopo

1. Una prima risposta **entro 7 giorni**.
2. La verifica e la valutazione della gravità (CVSS), di cui ti teniamo informato.
3. La correzione in una nuova versione, e l'avviso di sicurezza pubblicato quando la versione corretta è disponibile, con il tuo nome nei ringraziamenti se lo desideri.

Ti chiediamo di non rendere pubblici i dettagli prima dell'avviso, e comunque non oltre **90 giorni** dalla segnalazione, salvo accordi diversi.

### Che cosa non fare

- Non provare su installazioni che non sono tue: né la demo pubblica oltre il normale uso, né le istanze di KondoCloud o di altri amministratori.
- Niente attacchi che degradano il servizio, ingegneria sociale o accesso a dati di altri utenti oltre il minimo necessario a dimostrare il problema.

### Contribuire con la correzione

Se vuoi scrivere tu la correzione, ti aggiungiamo a un avviso di sicurezza privato con un fork privato temporaneo, così la correzione non è pubblica prima del rilascio. I contributi esterni richiedono il [Contributor License Agreement](https://cla-assistant.io/vince844/kondomanager-free), che puoi firmare da quel collegamento in qualsiasi momento.

## English

### Supported versions

| Version | Security fixes |
| :--- | :--- |
| 1.11.x (latest stable) | ✅ |
| Beta of the next version | ✅ in the following beta |
| 1.10.x and earlier | ❌ upgrade to the latest stable |

Security fixes are released in a new version and announced with a GitHub Security Advisory.

### Reporting a vulnerability

**Please do not open an issue, a pull request or a forum thread**: they are public, and would disclose the vulnerability before a fix is available.

Report it privately, from the repository's **Security** tab, with **"Report a vulnerability"**.

If you can, include: the KondoManager version, step-by-step instructions to reproduce, what it allows (which data, which role is needed) and a proof of concept if you have one.

### What happens next

1. A first reply **within 7 days**.
2. Verification and a severity assessment (CVSS), and we keep you informed.
3. A fix in a new version, and the advisory published once the fixed version is available, with credit to you if you wish.

Please do not disclose details before the advisory is published, and in any case not later than **90 days** after your report, unless agreed otherwise.

### What not to do

- Testing installations that are not yours: neither the public demo beyond normal use, nor KondoCloud instances or other administrators' installations.
- Denial of service, social engineering, or accessing other users' data beyond the minimum needed to demonstrate the issue.

### Contributing a fix

If you want to write the fix yourself, we will add you to a private security advisory with a temporary private fork, so the fix is not public before the release. External contributions require the [Contributor License Agreement](https://cla-assistant.io/vince844/kondomanager-free), which you can sign from that link at any time.
